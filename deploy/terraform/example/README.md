# ctaudit on EKS with Terraform

This is an example root module. It creates the IAM role that ctaudit uses through IRSA (IAM roles for service accounts) and installs the Helm chart from `deploy/helm/ctaudit` with that role set on the chart's ServiceAccount. Copy it into your infrastructure repository, or use it from here, and adjust it to fit.

## What it creates

- One least-privilege reader policy per entry in `log_buckets`, from the `iam/cloudtrail-audit-reader` module. Each policy allows `s3:ListBucket` under `AWSLogs/`, `s3:GetObject` on the objects there, and `kms:Decrypt` through S3 when you set `kms_key_arn`. ELB access logs use the same `AWSLogs/` layout, so the module covers them too.
- An IAM role whose trust policy accepts only the cluster's OIDC provider, the `sts.amazonaws.com` audience, and the subject `system:serviceaccount:<namespace>:<service_account_name>`. Every reader policy is attached to it.
- A `helm_release` of the local chart. Terraform builds the chart values from its variables and passes the role ARN in as `serviceAccount.roleArn`, so no values file has to be edited by hand.

## Before you apply

- The cluster needs an IAM OIDC provider. The module looks it up and fails if it is missing.
- The nodes must be able to pull the image named by `image_repository`. When the ECR repository is in another account, it needs a repository policy that allows the cluster's node role.
- Loki credentials never pass through Terraform, so they stay out of the state. Create a Secret with `CTAUDIT_LOKI_TOKEN`, or `CTAUDIT_LOKI_USER` and `CTAUDIT_LOKI_PASSWORD`, in the target namespace, and name it in `loki_existing_secret`.
- The ServiceMonitor and PrometheusRule need the Prometheus Operator CRDs. They are rendered only when `prometheus_release_label` is set.
- The `helm` provider gets a token with `aws eks get-token`, so the AWS CLI must be installed where Terraform runs.
- Add a backend in `versions.tf` before sharing the state.

## Usage

```bash
cd deploy/terraform/example
cp terraform.tfvars.example terraform.tfvars   # then edit it
terraform init
terraform plan
terraform apply
```

After the apply, check a scanner:

```bash
kubectl -n ctaudit logs deploy/ctaudit-cloudtrail
kubectl -n ctaudit port-forward svc/ctaudit-cloudtrail 8080:8080   # then open localhost:8080/report
```

Set `debug = true`, or `debug = true` inside one `scanners` entry, to see each listed prefix, object read, and tick decision in the pod log.

## Inputs and outputs

`log_buckets` keys become part of the policy names, `<role name>-<key>`. The role name defaults to `ctaudit-<cluster_name>` so installs into two clusters in the same account do not collide. Scanner fields left unset are not sent to the chart, so its defaults apply.
